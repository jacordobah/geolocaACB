# Matriz de dependencias entre equipos

**Catálogo local de GPS:** el adaptador YAML existe y se exige al habilitar control. Faltan aprobación de los valores operativos y autorización contextual de selección por `policy_id` en Gateway; no es una dependencia HTTP. Véase [políticas YAML](politicas-yaml.md) y [contrato Gateway](contrato-gateway-gps.md).

| Equipo | Debe implementar o acordar | Contrato que consume / expone | Datos, respuestas y autenticación | Ya puede probar / bloqueo |
| --- | --- | --- | --- | --- |
| GPS | Registrar condicionalmente control/lectura con verificador de credencial Gateway; mantener Redis, 24 h, recuperación y outbox | Expone salud y observaciones; control/lectura se habilitan por configuración completa | Bearer GPS por sesión; Bearer interno Gateway para control/lectura; errores 400/401/404/409/422/503 | Flujo sintético del binario disponible; operación real bloqueada por autorización contextual Gateway, políticas y contrato Python |
| Controlador administrativo (por definir) | Autorizar inicio/fin, asignar guía/recorrido/ruta, elegir política y entregar credencial al dispositivo | Consume `POST /tracking-sessions`, `GET /{id}`, `POST /{id}/finish` mediante Gateway | `trip_id`, `guide_id`, `geo_route_id`, `policy_id`, `Idempotency-Key`; 201/200, 409/422/503; identidad ante Gateway | Puede revisar contrato interno y test aislado; falta definir propietario, unicidad por recorrido y reemisión/rotación |
| Operaciones | Recibir y deduplicar novedades, persistir antes de acusar, administrar notificaciones | Expondrá recurso HTTP detrás de Gateway, aún no acordado | `gps.event.v1`, `Idempotency-Key=event_id`; 200/201 `gps.ack.v1` con mismo ID y estado durable; Bearer servicio/TLS | Receptor simulado verifica contrato provisional; faltan ruta del Gateway, credenciales y semántica de eventos |
| Python / propietario geográfico | Entregar versión oficial, asociaciones verificadas y extremos consistentes | Expone `GET /api/v1/routes/{route_id}` detrás de Gateway | `_id`, LineString, PE ordenados, IDs extremos, `geometry_version`, `association_status`; 200/404/409/422/5xx | Cliente Go probado con Gateway simulado; ruta consultable actual no alcanza `OperationalReady` sin campos adicionales |
| Gateway | Encaminamiento HTTP obligatorio, autenticación/autorización contextual y secreto interno exclusivo | Enruta entrada a GPS y salida GPS → Python / Operaciones | Acordar origen/rutas; verificar usuario/recorrido/política, preservar `Authorization` apropiado, `Idempotency-Key`, cuerpo, códigos y `no-store` | Puede usar [contrato](contrato-gateway-gps.md); faltan rutas públicas, reglas de autorización y topología de red |
| Presentación | Capturar GPS, mantener secuencia por sesión, proteger token y reintentar idénticamente | Consume `POST /{tracking_id}/observations`; lecturas sólo tras autorización específica | `sequence`, lat/lon, `accuracy_m`, `captured_at`; 201/200/400/401/409/413/415/503; Bearer de observación | Puede probar fixture sintético; falta entrega segura del token y acuerdo de frecuencia/lectura |

Los prefijos abreviados de rutas en la tabla pertenecen a `/api/v1/tracking-sessions`. Control y lectura están apagados por defecto, pero se registran al suministrar la configuración completa. Los recorridos reales dependen de los acuerdos externos indicados. La matriz de [habilitación](matriz-habilitacion.md) contiene procedimiento y verificación por endpoint.

Toda comunicación HTTP entre componentes pasa por Gateway. Redis y el archivo local de políticas son privados de GPS. GPS exige `GPS_GATEWAY_BASE_URL` y rutas absolutas separadas para consultas geográficas y eventos; las URL directas anteriores se rechazan. La configuración de red compartida, rutas, credenciales de servicio y propagación de errores/acuses necesitan acuerdo con Gateway.
