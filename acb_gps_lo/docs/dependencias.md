# Matriz de dependencias entre equipos

| Equipo | Debe implementar o acordar | Contrato que consume / expone | Datos, respuestas y autenticación | Ya puede probar / bloqueo |
| --- | --- | --- | --- | --- |
| GPS | Registrar control/lectura sólo con verificador real; mantener Redis, 24 h, recuperación y outbox | Expone salud y observaciones; handlers de control/lectura implementados | Bearer GPS por sesión; futuros Bearer de servicio con audiencia/capacidad/alcance; errores 400/401/403/404/409/422/503 | Prueba sintética integral y carga disponibles; producción bloqueada por identidad, políticas y contrato Python |
| Controlador administrativo (por definir) | Autorizar inicio/fin, asignar guía/recorrido/ruta, elegir política y entregar credencial al dispositivo | Consumirá `POST /tracking-sessions`, `GET /{id}`, `POST /{id}/finish` tras habilitación | `trip_id`, `guide_id`, `geo_route_id`, `policy_id`, `Idempotency-Key`; 201/200, 409/422/503; Bearer `tracking:create/read/finish` y alcance | Puede revisar OpenAPI y test aislado; falta definir propietario, identidad, unicidad por recorrido y reemisión/rotación |
| Operaciones | Recibir y deduplicar novedades, persistir antes de acusar, administrar notificaciones | Expondrá recurso HTTP a GPS, aún no acordado | `gps.event.v1`, `Idempotency-Key=event_id`; 200/201 `gps.ack.v1` con mismo ID y estado durable; Bearer servicio/TLS | Receptor simulado verifica contrato provisional; faltan ruta real, credenciales y semántica de eventos |
| Python / propietario geográfico | Entregar versión oficial, asociaciones verificadas y extremos consistentes | Expone `GET /api/v1/routes/{route_id}` | `_id`, LineString, PE ordenados, IDs extremos, `geometry_version`, `association_status`; 200/404/409/422/5xx | Cliente Go probado; ruta consultable actual no alcanza `OperationalReady` sin campos adicionales |
| Gateway | Encaminamiento, TLS y políticas de acceso cliente/servicio | Encaminamiento futuro hacia observaciones y lecturas autorizadas | Preservar `Authorization`, `Idempotency-Key`, códigos y `Cache-Control: no-store`; no confiar en cabeceras de identidad del cliente | Puede validar rutas/errores con OpenAPI; falta acuerdo de identidad y topología de red |
| Presentación | Capturar GPS, mantener secuencia por sesión, proteger token y reintentar idénticamente | Consume `POST /{tracking_id}/observations`; lecturas sólo tras autorización específica | `sequence`, lat/lon, `accuracy_m`, `captured_at`; 201/200/400/401/409/413/415/503; Bearer de observación | Puede probar fixture sintético; falta entrega segura del token y acuerdo de frecuencia/lectura |

Los prefijos abreviados de rutas en la tabla pertenecen a `/api/v1/tracking-sessions`. La API de control/lectura no está registrada en el binario actual. Ningún equipo debe usar el verificador de pruebas como identidad operativa. La matriz de [habilitación](matriz-habilitacion.md) contiene procedimiento y verificación por endpoint.
