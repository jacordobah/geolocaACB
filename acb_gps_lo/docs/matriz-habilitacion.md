# Matriz de habilitación y prerrequisitos operativos

**Catálogo YAML:** está implementado, pero es opcional y su ejemplo contiene sólo valores sintéticos. Configurar `GPS_POLICIES_FILE` carga y valida definiciones y su registro histórico en Redis; no habilita control ni lectura por sí solo. El binario ya puede registrar esos handlers con el modelo Gateway confiable, pero la integración real exige autorización contextual en Gateway, políticas aprobadas y rutas `OperationalReady`. Véase [políticas YAML](politicas-yaml.md) y [contrato Gateway](contrato-gateway-gps.md).

Estados: **H** = registrado por defecto; **D** = implementado y registrable sólo con configuración válida; **E** = requiere acuerdo o cambio externo para uso real. Una capacidad puede estar en D y E simultáneamente. El modo Gateway confiable verifica una credencial interna; el Gateway real y su autorización contextual aún deben integrarse.

| Funcionalidad / endpoint | Estado | Prerrequisitos y responsable | Configuración y permisos | Procedimiento de habilitación y verificación | Debe permanecer deshabilitada si… |
| --- | --- | --- | --- | --- | --- |
| `GET /health/live` | H | Proceso HTTP de GPS | `GPS_HTTP_PORT`; sin credencial | Construir y arrancar; comprobar HTTP 200 `alive` aun con Redis caído | El proceso no atiende HTTP |
| `GET /health/ready` | H | Redis accesible; GPS/infraestructura | `GPS_REDIS_ADDR`, `GPS_REDIS_PING_TIMEOUT`; sin credencial | Comprobar 200 `ready` con Redis y 503 `not_ready` al aislar Redis | Redis no responde; no se reinicia Go por un fallo de Python |
| `POST /api/v1/tracking-sessions` | D + E | Gateway autoriza consumidor, recorrido y política; Python entrega ruta `OperationalReady`; controlador aprueba inicio | `GPS_CONTROL_API_ENABLED=true`, origen/ruta Gateway, YAML, `GPS_GATEWAY_INTERNAL_TOKEN`, `GPS_CONTROL_CREDENTIAL_KEY`, `Idempotency-Key` | Configurar secretos externos y dependencias; comprobar 201/200/409/401/422 con ruta sintética; luego probar autorización Gateway real | Falta contexto autorizado, red privada, política operativa o aptitud geográfica; **el flag solo no basta** |
| `GET /api/v1/tracking-sessions/{tracking_id}` | D + E | Gateway autoriza consulta del recorrido; GPS verifica credencial interna | `GPS_CONTROL_API_ENABLED=true`, `GPS_GATEWAY_INTERNAL_TOKEN` | Comprobar 200 con secreto y 401 sin él; probar denegación contextual en Gateway | No hay autorización del consumidor en Gateway |
| `POST /api/v1/tracking-sessions/{tracking_id}/finish` | D + E | Controlador decide cierre; Gateway autoriza y enruta; GPS revoca credencial | Igual que control; cuerpo vacío | Comprobar cierre repetido 200, revocación, evento técnico y retención | No hay autoridad de cierre o autorización Gateway |
| `POST /api/v1/tracking-sessions/{tracking_id}/observations` | H **para sesiones aprovisionadas internamente**; E para uso real | Sesión técnica activa, credencial entregada al dispositivo, ruta apta y políticas de sesión; controlador, Presentación y Python | Bearer de observación exclusivo de sesión; `GPS_MAX_OBSERVATION_BYTES`, `GPS_REQUEST_TIMEOUT`, `GPS_MAX_OBSERVATION_AGE`, `GPS_FUTURE_SKEW` | En entorno aislado crear sesión sintética, enviar JSON y verificar 201, reintento 200, conflicto 409; integrar aprovisionamiento seguro antes de uso real | No existe sesión autorizada, credencial válida o aptitud geográfica; la credencial no permite lecturas/control |
| `GET /api/v1/tracking-sessions/{tracking_id}/latest-position` | D + E | Gateway autoriza lectura de ubicación sensible; GPS verifica secreto | `GPS_CONTROL_API_ENABLED=true`, `GPS_READ_API_ENABLED=true`, token interno y límites de lectura | Comprobar 200/204/410/401/503 y `Cache-Control: no-store` | Gateway no comprueba alcance/rol del lector |
| `GET /api/v1/tracking-sessions/{tracking_id}/positions` | D + E | Igual que lectura; Gateway autoriza cada página | Flags de control/lectura, token interno; `after_sequence`, `limit` <= `GPS_READ_MAX_PAGE_LIMIT` y <=100 | Verificar páginas ordenadas, cursor, huecos y expirados; 401 sin credencial | No hay autorización o política de lectura acordada |
| Evaluación de ruta y puntos reales | Implementada internamente; E | Gateway enruta a Python; Python entrega `geometry_version` oficial, `association_status=verified`, `endpoint_status=resolved`, IDs extremos y PE consistentes; propietario geográfico | `GPS_GATEWAY_BASE_URL`, `GPS_GATEWAY_ROUTES_PATH`, token de servicio si se acuerda, timeout/límite; radios y precisión aprobados en política de sesión | Probar contrato real a través del Gateway, `OperationalReady`, instantánea inmutable y evaluación; activar aprovisionamiento sólo entonces | Sólo hay ruta consultable o geometría calculable, sin aptitud operativa; huella local no sustituye versión oficial |
| Primera llegada, posteriores y desvíos | Implementado internamente; E para reglas operativas | Políticas temporales/geográficas aprobadas y sesión apta; controlador y Operaciones | Políticas fijadas en instantánea; no hay valores operativos por defecto | Probar transiciones con sesiones autorizadas y acuerdar significado de cada evento | Faltan umbrales, ventanas o acuerdo administrativo; `inside` no equivale a llegada administrativa |
| Outbox y recuperación autónoma | H | Redis disponible y AOF conservado; GPS/infraestructura | `GPS_RECOVERY_POLL`, Redis AOF, `noeviction` | Simular escritura parcial y reinicio aislado; verificar recuperación y ausencia de duplicados | Redis sin capacidad o índice corrupto no reparable; escalar intervención, sin borrar eventos |
| Despacho GPS → Operaciones | D + E | Gateway enruta al receptor durable con deduplicación por `event_id` y acuse `gps.ack.v1`; Operaciones, Gateway e infraestructura | `GPS_OPERATIONS_DELIVERY_ENABLED=false`; `GPS_GATEWAY_BASE_URL`, `GPS_GATEWAY_EVENTS_PATH`, `GPS_OPERATIONS_TOKEN`, timeout, trabajadores, lease, reintentos y retención | Acordar esquema/receptor, ruta Gateway y TLS; configurar secreto fuera de Git, habilitar flag, verificar acuses y reintentos con evento sintético | Receptor, ruta o contrato no acordados; **no activar sólo por tener una URL** |
| Autenticación entre componentes | D + E | Gateway administra consumidores/alcances y distribuye credencial interna; GPS verifica secreto | `GPS_GATEWAY_INTERNAL_TOKEN` aleatorio y canal privado; permisos contextuales en Gateway | Verificar 401 por secreto incorrecto y denegación de recorrido/política en Gateway; acordar rotación | Cabeceras de identidad del cliente, red expuesta o secreto ausente |

**Dependencia externa frente a configuración:** el despacho está deshabilitado por una variable **y** por la falta de receptor acordado detrás de Gateway. Control y lectura se registran condicionalmente; su integración real requiere autorización contextual en Gateway y ruta apta de Python. `GPS_GATEWAY_ROUTES_PATH` por sí sola no vuelve una ruta `OperationalReady`. Las variables antiguas `GPS_PATHS_BASE_URL` y `GPS_OPERATIONS_EVENT_URL` se rechazan si contienen valores.

**Responsables por equipo:** GPS mantiene adaptadores, validaciones, recuperación y pruebas; el controlador administrativo autoriza inicio/fin, política e identidad de servicio; Python declara versión y asociaciones; Operaciones persiste/deduplica eventos y confirma; Gateway enruta con transporte seguro; Presentación protege la credencial limitada y reintenta observaciones idénticas. Ningún equipo debe tomar un HTTP 200 de liveness como prueba de capacidad operativa de seguimiento.

## Cambios necesarios para pasar de prueba aislada a integración

**Bloqueo geográfico adicional comprobado:** el RF-09 local describe rutas 542 cuyo origen es un colegio, mientras `OperationalReady` exige que `start_meeting_point_id` sea el primer PE. La semántica de extremo y el tratamiento de rutas 542 deben acordarse entre Python y GPS; quizá requieran modificar Go en un incremento posterior. Publicar sólo `geometry_version` y `association_status` no resuelve este caso. Consulte [contrato-geografico.md](contrato-geografico.md).

| Capacidad | Cambio interno en GPS | Acuerdo o cambio externo | Configuración, aceptación y bloqueo |
| --- | --- | --- | --- |
| Crear, consultar y cerrar sesiones | Composición y verificador de secreto interno implementados; validar configuración de entorno | Gateway autoriza recorrido/política; controlador decide inicio/fin; Python entrega ruta apta | Configurar flags, secretos, catálogo y ruta; probar 201/200/409/401/422/503, cierre y revocación. El flag solo no basta |
| Recibir GPS real | Ningún cambio del endpoint es suficiente por sí solo; depende de sesiones aptas aprovisionadas | Controlador entrega token de sesión de forma segura; Presentación acuerda cadencia y reintentos; Python publica ruta apta | Bearer exclusivo; probar 201/200/409/401 y TTL >=24 h. No usar IDs como credencial ni sesión sintética en producción |
| Leer última posición e historial | Registro condicional implementado con `GPS_READ_API_ENABLED`; límites existentes | Gateway autoriza rol y recorrido para cada consulta; acordar acceso con controlador y Presentación | Probar 200/204/410/401/503, páginas y no-store; sin autorización contextual en Gateway, mantener flag apagado |
| Evaluar ruta real y eventos geográficos | Mantener guard `OperationalReady`; no basta configurar la ruta del Gateway | Gateway publica la ruta geográfica; Python publica versión oficial y asociación verificada; controlador aprueba política geográfica/temporal y ruta | Validar LineString/PE/extremos/huella en sesión; probar evaluación e inmutabilidad. Si faltan metadatos o autorización, no aprovisionar |
| Despachar a Operaciones | El emisor ya existe; habilitarlo sólo tras verificar contrato, credencial y conectividad al Gateway | Gateway publica ruta y propaga acuse; Operaciones implementa receptor durable, deduplicación por `event_id` y acuse `gps.ack.v1`; acuerdan TLS y manejo administrativo | Configurar `GPS_OPERATIONS_DELIVERY_ENABLED`, `GPS_GATEWAY_BASE_URL`, `GPS_GATEWAY_EVENTS_PATH`, token y límites; probar 201/200, duplicado `already_persisted`, pérdida de respuesta, reintentos y bloqueo. Mantener apagado sin receptor acordado |
| Autenticación de servicio | Verificador de secreto Gateway implementado; restringir acceso directo y custodiar secreto | Gateway/infraestructura definen rotación, red privada y autorización contextual; controlador define reglas | Probar token correcto/incorrecto y Bearer GPS en control/lectura; probar denegaciones de alcance en Gateway. El secreto estático no codifica vencimiento de usuario |

**Estado actual:** el despacho está deshabilitado por configuración (`GPS_OPERATIONS_DELIVERY_ENABLED=false`) y bloqueado por la falta del receptor externo acordado. Control y lectura ya disponen de composición condicional Go; el arranque falla cerrado si se activan sin requisitos. Observaciones están registradas, aunque su uso con recorridos reales depende de aprovisionamiento y ruta apta. La prueba aislada no certifica Gateway, Administración ni Python reales.
