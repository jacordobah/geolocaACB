# Limitaciones conocidas y decisiones pendientes

| Tema | Estado comprobado | Decisión o trabajo externo |
| --- | --- | --- |
| Control y lectura | Handlers y casos de uso probados, pero ausentes del mux operativo; `GPS_CONTROL_API_ENABLED=true` se rechaza | Definir controlador, proveedor verificable, capacidades y alcances, política geográfica autorizada, transporte TLS y ciclo de credenciales |
| Rutas reales | Cliente Python y motor geográfico disponibles; `OperationalReady` exige versión oficial y asociación verificada que la respuesta actual no garantiza | Propietario Python debe ampliar contrato y certificar PE/extremos; controlador aprueba radios y tiempos |
| Referencia de extremo externo | `OperationalReady` sólo exige un `end_meeting_point_id` presente; si no pertenece a la lista de PE, Go no puede distinguir un colegio legítimo de una referencia rota. Tampoco verifica un umbral de `endpoints.*.confidence` | Acordar con Python tipo/semántica de extremo y confianza exigible; después decidir si hay que reforzar el guard Go. No resolver sólo con documentación |
| Inicio de ruta 542 en colegio | El RF-09 local de Python describe rutas 542 que empiezan en colegio; Go exige que `start_meeting_point_id` sea el primer PE. Es posible un rechazo aun después de recibir versión/estado de asociación | GPS y Python deben acordar representación de origen escolar y aptitud para este sentido de recorrido; requiere revisión de contrato y posiblemente código Go, no un ajuste documental silencioso |
| Operaciones | Contrato HTTP `gps.event.v1`/`gps.ack.v1` probado sólo con receptor simulado; entrega deshabilitada | Operaciones debe aceptar/deduplicar durablemente y acordar URL, identidad, semántica y retención |
| Credencial HMAC | Clave externa >=32 bytes; derivación HMAC-SHA256 de ID; Redis conserva SHA-256 del token. La ventana de reemisión evita guardar texto claro | Establecer almacén seguro, respaldo/rotación de clave y protocolo autorizado de reemisión/rotación. Perder la clave impide reemitir tokens existentes; la rotación inmediata hace que nuevos reintentos de provisión choquen con el digest previo |
| Reservas de idempotencia | `gps:control:request:{hash}` no expira; un reintento no crea otra sesión por vencimiento prematuro | Acordar horizonte máximo de reintentos y tombstones antes de limpiar reservas. Sin acuerdo, el almacenamiento crece y la reserva se conserva |
| Provisioning abandonado | Índice y plan durables permiten recuperación acotada sin nuevo GPS. Un huérfano de más de 24 h no se activa automáticamente; se reintenta y registra error | Definir intervención, cierre/retención de reserva y política administrativa para solicitudes nunca completadas |
| Sesiones activas abandonadas | GPS no cierra automáticamente una sesión por silencio, para no tomar una decisión administrativa implícita | Controlador define vencimiento/heartbeat y autoridad de cierre; hasta entonces persiste estado activo |
| Redis standalone | AOF `always`, `noeviction`, TTL individual; pruebas de reinicio aislado satisfactorias | Infraestructura define respaldo, disponibilidad, tamaño memoria/disco y recuperación de pérdida de nodo/volumen. Falta de memoria o Redis caído impide aceptar con seguridad |
| Pruebas de carga | Se ejecutaron escenarios sintéticos cortos con 100/500/1000 sesiones; sin errores observados, pero con retraso creciente de eventos | Repetir con duración sostenida, red real, TLS, políticas y receptor operativos, límites de recursos y presupuesto de latencia acordados |
| Limpieza de índices/eventos corruptos | Recuperación usa lotes; eventos pendientes no se borran. Planes irrecuperables se registran y aplazan; un índice corrupto requiere intervención | Definir observabilidad/operación manual y política segura de limpieza, sin `FLUSHDB` operativo ni pérdida de eventos |

La API de observaciones está registrada, pero no hay un aprovisionamiento público operativo capaz de crear sesiones sobre rutas reales; los tests usan sesiones e identidades sintéticas. No se debe interpretar `GET /health/ready` como garantía de que Python, Operaciones o el controlador administrativo estén listos. Las pruebas AOF no prueban pérdida física de volumen. Las mediciones de carga no son un SLA.
