# Despliegue independiente con Docker

## Catálogo local opcional

`compose.yaml` monta `./config/tracking-policies.yaml` en `/etc/acb-gps/tracking-policies.yaml` como solo lectura. El binario sólo lo carga si `GPS_POLICIES_FILE` tiene esa ruta. Por defecto la variable está vacía; el YAML incluido es sintético y **no autoriza seguimientos reales**. Si se configura, el archivo debe existir y ser válido; el arranque también comprueba en Redis la huella histórica de cada ID, por lo que requiere Redis disponible. Para publicar otra revisión, edite el archivo montado y reinicie controladamente sólo Go, sin recompilar ni reiniciar Redis. Consulte [políticas YAML](politicas-yaml.md). Control se registra únicamente con `GPS_CONTROL_API_ENABLED=true` y las dependencias de seguridad completas.

Desde `acb_gps_lo/`: `docker compose -f compose.yaml config -q`, `docker compose -f compose.yaml build gps`, `docker compose -f compose.yaml up -d`. El proyecto Compose se llama `acb-gps-lo` y crea sus propios servicios `gps` y `redis`, red y volumen `gps-redis-data`. No incorpora Python ni MongoDB. Por defecto el binario escucha en el puerto interno 8080 y publica **sólo** `127.0.0.1:8081` en el host; Redis escucha en `redis:6379` dentro de la red privada y no publica puerto al host. `GET http://127.0.0.1:8081/health/live` comprueba proceso; `/health/ready` comprueba Redis. Readiness no comprueba Python ni Operaciones.

Copie `.env.example` a un `.env` local fuera de Git y ajuste los parámetros. No coloque secretos reales en Dockerfile, código, documentación o `.env.example`. Redis usa volumen persistente, AOF `appendfsync always` y `maxmemory-policy noeviction`; `REDIS_MAXMEMORY=512mb` es sólo un valor inicial, no capacidad garantizada. Mida memoria, AOF, espacio y latencia antes de aumentar carga o cambiar fsync. Un Redis standalone pierde datos si pierde el volumen/nodo; se requiere plan externo de respaldo/alta disponibilidad para garantías superiores.

Para la integración HTTP, configure `GPS_GATEWAY_BASE_URL` con el **origen HTTP(S) del Gateway alcanzable desde el contenedor GPS**, sin prefijo de ruta; `GPS_GATEWAY_ROUTES_PATH` con la ruta absoluta completa de consulta terminada en `/{route_id}`, y `GPS_GATEWAY_EVENTS_PATH` con la ruta absoluta completa del receptor de eventos. Los valores concretos los acuerda Gateway. Las rutas se validan y no se concatenan con prefijos de servicio. `GPS_PATHS_BASE_URL` y `GPS_OPERATIONS_EVENT_URL` son obsoletas: un valor no vacío causa error de configuración, sin fallback directo. Si el Gateway requiere credencial de servicio para consultas geográficas, proporcione `GPS_GATEWAY_ROUTES_TOKEN` de forma segura. El despacho utiliza `GPS_OPERATIONS_TOKEN` como credencial Bearer hacia Gateway y conserva el acuse durable de Operaciones. El cliente geográfico se invoca al aprovisionar, no en liveness/readiness ni por posición.

Conecte GPS y Gateway mediante una red privada acordada y enrutable; la red externa no se crea automáticamente. Para un entorno con esa red, defina `GPS_GATEWAY_NETWORK` con su nombre acordado y use `docker compose -f compose.yaml -f compose.gateway.yaml config -q` y luego `docker compose -f compose.yaml -f compose.gateway.yaml up -d`. El archivo adicional sólo conecta **gps** a esa red; Redis permanece en `gps-net`. No conecte GPS directamente a las redes privadas de Python u Operaciones para eludir Gateway. Presentación y el controlador administrativo entran por Gateway; éste debe preservar Bearer, `Idempotency-Key`, códigos HTTP y `Cache-Control: no-store`. Restringir el acceso directo al puerto de GPS es obligatorio para el modelo Gateway confiable; el puerto de desarrollo está limitado a loopback. GPS verifica `GPS_GATEWAY_INTERNAL_TOKEN`, independiente del Bearer de observación, pero confía en la autorización contextual realizada por Gateway. No confía en cabeceras de identidad de cliente. Mantenga `GPS_OPERATIONS_DELIVERY_ENABLED=false` hasta acordar ruta, receptor, acuse durable y autenticación.

Para habilitar el control en un entorno de integración: inyecte fuera de Git dos secretos **distintos**, aleatorios de 32 a 64 bytes codificados base64url sin padding (`GPS_GATEWAY_INTERNAL_TOKEN` y `GPS_CONTROL_CREDENTIAL_KEY`); configure `GPS_GATEWAY_BASE_URL`, `GPS_GATEWAY_ROUTES_PATH`, `GPS_POLICIES_FILE=/etc/acb-gps/tracking-policies.yaml`, `GPS_CONTROL_ISSUANCE_WINDOW` y `GPS_CONTROL_REQUEST_TIMEOUT`; establezca `GPS_CONTROL_API_ENABLED=true`. `GPS_READ_API_ENABLED=true` registra también última posición e historial y exige control habilitado. Falta acordar los valores operativos del YAML y la ruta geográfica apta; no use los ejemplos sintéticos en recorridos reales. Los secretos pasados por variables de Compose son visibles para quien pueda inspeccionar el contenedor: proteger el acceso a Docker y preferir un mecanismo externo de secretos en despliegues posteriores. Véase [contrato Gateway](contrato-gateway-gps.md).

El healthcheck de Go ejecuta el propio binario (`/acb-gps healthcheck`) y el de Redis usa `redis-cli ping`. Un fallo transitorio de Python u Operaciones no mata Go; Redis indisponible produce readiness 503 y liveness 200. Durante SIGTERM el servidor deja de aceptar conexiones y espera hasta `GPS_SHUTDOWN_TIMEOUT`; las reclamaciones de eventos no confirmadas quedan recuperables. El despliegue se detiene sin borrar datos con `docker compose -f compose.yaml down` (sin `-v`). Revise estado con `docker compose -f compose.yaml ps`, logs con `docker compose -f compose.yaml logs gps redis`, y compruebe red/URL desde un contenedor temporal autorizado. No reinicie ni reemplace los servicios Python/MongoDB existentes para verificar GPS.

Para integración real aún faltan autorización contextual en Gateway, ruta Python `OperationalReady`, controlador administrativo, política aprobada y receptor de Operaciones. La [matriz](matriz-habilitacion.md) detalla pasos y verificaciones. El Dockerfile construye con Go 1.27.3 en etapa separada y ejecuta sólo el binario estático como usuario no privilegiado en Distroless; compilador y dependencias de build no llegan a la imagen final.
